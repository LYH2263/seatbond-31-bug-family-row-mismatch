# SeatBond

影院连座锁座：按场次厅图查找连续空座，过道列断开，冲突检测既有持座。

家庭排（亲子区）：影厅可把若干整排标为家庭排，座位图按排金色高亮。
带儿童标记的锁座**只能**落在家庭排内；普通锁座默认**避开**家庭排，把亲子区留给家庭观众。
过道切断与家庭排过滤同时生效——家庭排内连续段被过道切短或已占满时，亲子请求直接失败，
冲突原因记为“家庭排内连续空座不足”，不会退到非家庭排凑合成功。

## 启动

```bash
docker compose up --build
```

| 服务 | 地址 |
| --- | --- |
| 前端 | http://localhost:4100 |
| API | http://localhost:9100 |
| API 文档 | http://localhost:9100/docs |
| Postgres | localhost:5442 |

健康检查：`GET http://localhost:9100/api/health`

## 页面

- `/halls` — 影厅（点击排号维护家庭排标记并保存）
- `/showtimes` — 场次
- `/seatmap` — 座位图（大网格热力，家庭排整排金色高亮）
- `/hold` — 锁座（“带儿童”开关：开启后只在家庭排内找连座）
- `/orders` — 订单（区分普通 / 带儿童·家庭排）
- `/conflicts` — 冲突

## 接口

- `PUT /api/halls/{id}/family-rows`，请求体 `{"family_rows": [6, 7]}`（去重排序；越界 422，影厅不存在 404）。
- `POST /api/holds` 增加 `with_children: true|false`；亲子失败返回 409 `家庭排内连续空座不足`，
  普通区失败返回 409 `非家庭排连续空座不足`。
- `GET /api/seatmap/{showtime_id}` 返回顶层 `family_rows`，每个 cell 带 `is_family_row`。

## 使用说明

1. 在影厅页点排号维护家庭排；在场次页确认排期。
2. 打开座位图查看金色家庭排与占用热力；锁座页输入人数，带儿童时勾选开关。
3. 订单页查看持座结果；冲突页查看失败原因（家庭排不足 / 普通区不足 / 持座重叠）。

## 开发与测试

```bash
docker compose exec api pytest -q
```

种子数据中的“星际旅人”场次：家庭排（6、7 排）已被过道与既有持座切到不足 5 连座，
5 人亲子请求必然失败，而非家庭排仍有空位，普通 5 人请求可以成功。
